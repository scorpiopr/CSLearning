## 🎯 经典三状态模型
在操作系统中，一个进程从创建到结束，最核心的包含以下三种基本状态：

      【就绪 (Ready)】  —— 被调度选中 ——>  【运行 (Running)】
            ▲                                    │
            │                                    │ 发生阻塞事件
        事件发生                                 │ (如等待I/O)
            │                                    ▼
            └─────────────── 【阻塞/等待 (Blocked/Waiting)】


   1. 就绪状态 (Ready)
   * 定义：进程已经获得了除 CPU 以外的所有必要资源（如内存空间、全局变量等），只要系统分配给它 CPU 时间片，就可以立即执行。
      * 特征：万事俱备，只欠 CPU。在内存中通常有多个进程处于就绪状态，排成一个就绪队列。
   2. 运行状态 (Running)
   * 定义：进程已经获得 CPU 资源，其程序正在 CPU 上执行。
      * 特征：在单核 CPU 系统中，任何时刻只能有一个进程处于运行状态；在多核 CPU 中，可以有多个进程同时处于运行状态。
   3. 阻塞状态 / 等待状态 (Blocked / Waiting / Sleep)
   * 定义：进程因为等待某件事件发生（如等待 I/O 操作完成、等待信号量、调用了 sleep() 或是等待锁）而暂时无法继续执行。
      * 特征：即使此时把 CPU 闲置给它，它也无法运行。系统会把它们排入阻塞队列。

## 🔄 核心状态转换触发条件
面试中经常会要求你口述或者画出状态转换图，关键的转换逻辑如下：

* 就绪 → 运行：进程调度程序（Scheduler）选中了就绪队列中的某个进程，为其分配了 CPU 时间片。
* 运行 → 就绪：
1. 时间片用完：在分时操作系统中，进程分配的时间片耗尽。
   2. 被抢占：一个更高优先级的进程进入就绪队列，操作系统剥夺了当前进程的 CPU 使用权。
* 运行 → 阻塞：进程在执行过程中主动申请了需要等待的资源。例如：读取磁盘文件（I/O）、等待网络数据、尝试获取一把已经被锁住的互斥锁。
* 阻塞 → 就绪：进程等待的事件已经完成（如磁盘数据读入内存、网络数据包到达）。此时进程不能直接变成运行态，必须先进入就绪队列排队。

## 🚀 现代操作系统的扩展状态（五状态与七状态）
面试时，如果你能主动提及现代操作系统的扩展状态，会大大增加面试官对你底层功底的认可：

   1. 创建状态 (New)：进程正在被创建（分配 PCB、加载代码），还没有提交到就绪队列。
   2. 结束状态 (Terminated / Zombie)：进程已经执行完毕或被异常终止，正在等待父进程回收其剩余资源（即常说的僵尸进程）。
   3. 挂起状态 (Suspended)：当内存严重不足时，操作系统会将一些暂时不运行的进程（无论是就绪还是阻塞）的代码和数据交换（Swap）到磁盘的虚拟内存（SWAP 分区）中。
   * 就绪挂起 (Ready-Suspended)：进程在磁盘中，只要换入内存即可进入就绪。
      * 阻塞挂起 (Blocked-Suspended)：进程在磁盘中，且还在等待某事件发生。

## ⚠️ 面试高频追问（避坑指南）

* 追问 1：阻塞态能不能直接变成运行态？
* 答案：不能。哪怕 CPU 此时完全空闲，阻塞态进程在等待事件完成后，也必须先进入就绪队列。由操作系统调度器统一分配 CPU。
* 追问 2：进程和线程的状态是一样的吗？
* 答案：在现代操作系统（如 Linux）中，CPU 调度的基本单位其实是线程（Lightweight Process）。上述状态机模型同样适用于线程。Linux 内核中用 TASK_RUNNING 统一表示就绪和运行态，用 TASK_INTERRUPTIBLE / TASK_UNINTERRUPTIBLE 表示阻塞态。
